# FORGE milestone 1 implementation plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** Create and fund a bank-controlled test-token vault; prove direct-call authorization without deployment.

**Architecture:** One Anchor program stores immutable vault configuration and controls a legacy SPL token account through a PDA. Treasury alone signs creation and funding. Real compiled program tests run inside LiteSVM; no RPC deployment is authorized.

**Tech Stack:** Anchor 1.2.0 (Rust program and generated IDL), legacy SPL Token, LiteSVM, pinned Nix development tools.

---

## Acceptance and boundaries

- Creation uses treasury + 32-byte vault ID PDA seeds, two distinct nondefault approvers, an explicitly selected six-decimal mint, immutable treasury token destination and positive ordered principal limits.
- Stored mint/token account and PDA authority prevent substitution. Funding moves exactly 10,000,000,000 base units in the standard fixture, only from treasury-owned accounts, through checked SPL transfer.
- Real runtime tests verify account state, token accounting, missing/unauthorized signatures, invalid configuration, wrong mint/program/ownership, cross-vault substitution, insufficient/zero funding and unsuccessful direct token theft. Assert specific failure codes and unchanged balances.
- No loans, withdrawals, API, SDK package or screens. Funds remain locked at this milestone. No keys tracked or printed. No deployment, including automatic `anchor test` deployment.
- LiteSVM is not a local validator. Milestone exit remains blocked pending separate permission for a disposable loopback-validator deployment/test.

## Task 2: Red, then green direct program tests

Files: `programs/forge/src/lib.rs`, `programs/forge/tests/vault.rs`.

1. Write direct runtime tests first; use ABI-only handler stubs to obtain a runnable failure at instruction behavior rather than compilation.
2. Run focused LSP diagnostics, SBF build and tests; record expected red failure.
3. Implement `create_vault` and `fund_vault` using Anchor constraints and SPL `transfer_checked` only.
4. Rebuild and run focused then full test suite. Fix failures without relaxing security assertions.

Expected commands: `anchor build`, `cargo test --locked -p forge --test vault`, `cargo fmt --all -- --check` (inside pinned shell). Build is permitted; deployment is not.
